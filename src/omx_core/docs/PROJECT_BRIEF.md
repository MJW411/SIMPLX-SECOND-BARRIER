# 프로젝트 설명 (PROJECT BRIEF)

> 설계 판단의 기준 문서. 사용자가 준 1부 원문을 그대로 옮겼다.

■ 1부: 프로젝트 설명

1. 개요
산업현장 로봇 안전을 위한 "세컨드 배리어"(보조 안전장치) 시제품이다. 작은 AI 컴퓨터 하나(Jetson Orin Nano Super + 1TB SSD)로 서버실 없이 인식·판단·녹화·DB·관리 웹까지 처리해, 경제적이고 간편한 하드웨어·소프트웨어 서비스라는 사업성을 보여주는 것이 목표다. 소프트웨어 최적화(적은 메모리·연산)가 중요한 평가 요소다.

2. 하드웨어 (전체 구성)
- Jetson Orin Nano Super(JetPack 6.2, Ubuntu 22.04, 메모리 8GB 공유), 1TB SSD. 하드웨어 영상 인코더(NVENC)가 없으므로 녹화는 CPU 소프트웨어 인코딩으로 가볍게 한다.
- Intel RealSense D435i: 로봇 주변 사람 감지와 거리 측정, 이벤트 녹화용 RGB.
- 모노 USB 카메라: 입구에서 헬멧 착용 감지.
- ROBOTIS OMX-F 팔로워(5축 + 그리퍼, 리치 약 40cm).
- Arduino Nano: 컨베이어 모터 드라이버 제어, 근접센서 1·2, 화재 감지 센서, 출입문 제어.
- 지금 보유한 것은 로봇팔과 D435i뿐이다. 없는 장치는 교체 가능한 어댑터로 설계하고, 제어판에서 조작하는 가상 장치(센서1·센서2·화재·문 버튼)로 대신 시험할 수 있게 한다.

3. 기능
3-1 입구 헬멧: 모노 카메라로 헬멧 착용을 감지해 출입문을 연다. 바운딩 박스 검출, 저해상도·저프레임·필요할 때만 추론. 미착용·불확실이면 닫힘 유지. 입구 카메라 결과는 문 제어에만 쓰고 로봇 거리 판단에 섞지 않는다(벽 너머 사람을 가깝다고 오판하지 않게).
3-2 사람 접근: D435i 깊이 + YOLO 세그멘테이션으로 사람을 찾고, 사람 3D 점과 로봇 각 링크(로봇 베이스 기준 FK로 계산) 사이 최소거리를 구한다. 감속 거리 안이면 감속, 정지 거리 안이면 정지(자리 유지). FK가 어려우면 카메라로 로봇 위치를 인식하는 대안을 쓴다. 감시 구역은 로봇 베이스 기준 3D로 정한다.
3-3 사라짐 정지: 사람이 출구 영역(화면 가장자리, 출입문, 감시 구역 밖)이 아닌 곳에서 갑자기 사라지면(로봇·작업대 뒤로 가려짐) 정지를 유지하고 관리자 확인으로만 해제한다. 사람별 ID 없이 직전/현재 프레임 검출의 1:1 위치 매칭으로 판정한다. 다른 사람이 안전거리에 나타나도 해제되지 않는다. 짧은 인식 끊김은 유예시간 안에 같은 위치에서 다시 보이면 원래 판단으로 복귀한다.
3-4 재가동: 정지 후 자동 재가동은 없다. 사람이 멀어진 뒤 관리자가 확인 버튼을 누르면, 그 순간 상태(사람 없음, 센서 정상, 미해결 사라짐 없음)를 다시 검사한 뒤 재가동한다.
3-5 녹화: D435i RGB를 2초 조각으로 상시 녹화하고 최근 60초만 보관한다. 이벤트가 나면 전 n초 + 후 m초 조각을 이어 클립으로 저장한다. 알림은 클립 완성을 기다리지 않고 즉시 보낸다. n·m·L(컨베이어 후 구간)은 관리자가 제어판에서 설정한다(초기 8/16/16초, 설정 한도는 시스템 설정).
3-6 이벤트 DB: 사람 접근·사라짐·컨베이어 이상·화재 이벤트와 클립을 SQLite에 쌓는다. SSD 전체 용량의 50%를 데이터 예산으로 두고, 넘으면 오래된 것부터 지운다(FIFO). 화재·미확인 이벤트는 보호한다.
3-7 관리자 웹·앱: 로그인 인증, 이벤트 목록·영상 재생, 즉시 알림, 재가동 승인, 녹화 길이 설정. 휴대폰에서도 쓰도록 PWA로 만든다. 현장 Wi-Fi 안에서 동작한다.
3-8 컨베이어 이상: 센서1 감지 후 일정 시간(컨베이어 속도 시험으로 결정) 안에 센서2가 감지하지 않으면 이벤트·녹화(전 n초·후 L초, 기준은 시간 초과 판정 시점)·알림. 제한시간이 길어 센서1 통과 장면이 빠질 수 있으면 경고만 한다.
3-9 화재: 아두이노가 젯슨을 기다리지 않고 즉시 출입문을 연다. 로봇은 사람에게 해가 없는 홈 위치로 이동하되, 복귀 중에도 사람 감지가 우선이다(사람이 가까우면 멈춤, 미해결 사라짐이 있으면 복귀 금지). 화재는 다른 모든 이벤트보다 우선한다. 녹화는 전 n초부터 관리자 "상황 종료"까지 이어지고, 그동안 로봇은 홈에서 벗어나지 않는다.
3-10 로봇 작업(픽앤플레이스 순환): 컨베이어 끝 센서2에 물체가 감지되면 벨트가 멈추고, 로봇이 집어서 센서1 쪽에 놓고, 벨트가 다시 돈다. 사이클 사이에는 홈에서 대기한다. 정지하면 그리퍼는 물체를 계속 쥐고, 재개 시 다음 지점으로 저속 접근한다(단계 건너뛰기 없음). 집기·놓기 실패를 판정한다. 부팅 시 자동으로 움직이지 않는다.
3-11 티칭: 홈 위치와 작업 자세는 키보드로 TCP(로봇 베이스 기준 x·y·z·그리퍼 기울기)를 조금씩 움직여 저장한다. 키를 누르는 동안만 움직인다. 5축이라 좌우 방향은 베이스 회전에 묶인다. 제어판에서 홈을 지정하고 자세 순서로 반복 동작을 만든다.
3-12 정비 모드: 피규어·물체를 놓거나 치울 때 로봇 구동을 막는다. 인식과 사라짐 기록은 계속한다.
3-13 가중치: ~/models의 가중치를 사람이 제어판에서 골라 쉽게 교체한다. 가능하면 한 모델로 두 카메라를 처리해 메모리를 아낀다(사람 세그멘테이션 + 헬멧 검출).

4. 상태 우선순위
화재 > 정지(사람 근접·사라짐·고장) > 감속 > 컨베이어 이상 > 정상. 카메라 끊김·인식 멈춤·통신 끊김 같은 고장은 정지로 처리한다.

5. 설계 원칙
- 판단은 한 곳(안전 관리자), 로봇 명령도 한 통로(실행기)로만 한다. 로봇은 "움직여도 됨" 허가가 계속 들어올 때만 움직이고, 허가가 끊기면 멈춘다(프로그램이 죽어도 정지).
- 아두이노는 젯슨 없이도 화재 시 문 개방, 젯슨 응답이 끊기면 컨베이어 정지를 스스로 한다.
- 실제 장치와 가상 장치, 실제 카메라와 녹화 영상을 같은 인터페이스로 바꿔 끼울 수 있게 한다.
- 리소스를 적게 쓰는 방법을 우선한다. Isaac ROS NITROS 같은 선택지는 실측으로 비교해 이득이 있을 때만 쓴다.
- 사용자(시연자·관리자)에게는 웹 제어판 하나로 모든 조작을 제공하고, 개발자에게는 모듈이 분리된 읽기 쉬운 코드와 한 줄 실행을 제공한다.

6. 시연 환경
작업대 위 축소 시연이다. 사람 대신 키 14cm 피규어(실제의 약 1/12)를 손으로 옮긴다. 실제 손·팔도 사람으로 인식하며, 손이 작업대에 들어오면 로봇이 멈추는 게 정상이다. 피규어와 실제 사람은 거리 기준을 따로 둔다.
